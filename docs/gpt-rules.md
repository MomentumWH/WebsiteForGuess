# GPT 调用规则

项目的持续规则位于根目录 [AGENTS.md](../AGENTS.md)，用于 GPT 辅助开发、工具调用和内容生成。

1. 禁止爬取网页数据，包括 HTML/DOM 解析、浏览器提取及第三方爬虫服务。已授权的官方 JSON API、本地文件和已有缓存可继续使用。
2. 禁止输出违禁词汇。用户确认当前先采用内容规范，词库后续补充；不宣称已经具备完整的自动过滤能力。

当前项目没有 GPT API 调用链，因而本次设置的是开发与生成规则，不是模型供应商的账户设置。未来接入模型时，应把规则加入服务端统一指令，并在具体词库确定后增加服务端输出检查。

现有 UEFA 球员名单网页请求与解析代码已移除；名单仅从同赛季本地缓存读取。没有缓存时使用 FPL 官方名单，UEFA 球员关联、号码和头像可能缺失，显示实际可用字段。比赛及逐场统计继续通过官方 JSON API 同步，不回退至网页抓取。

## 规范范围

本文约束后续 GPT 辅助分析、代码修改与内容生成。项目级入口为 `AGENTS.md`；执行任务前应同时阅读本文和 [调用记录](gpt-call-log.md)。

“一次调用”以一项用户任务为记录单位，不等同于每一次终端命令、文件读取、函数执行或模型供应商网络请求。同一任务的工具执行、重试和子代理工作归入同一记录；关键失败和验证结果仍需分别说明。后续新任务即使与上一任务相关，也应分配新编号。

本规范不改变现有数据来源、内容要求或子代理数量限制，也不要求为增加记录而接入外部平台。

## Vue 脚本注释规范

### 适用对象

- 本项目 Vue 文件的 `<script>` 和 `<script setup>` 中，新增或修改的命名方法、具名箭头函数。
- 计算属性、监听器、生命周期、事件回调和具有独立业务职责的异步回调。
- 简单内联的数组筛选、排序、映射表达式，可由所属方法的头部或关键步骤注释统一解释，避免给同一段逻辑重复堆叠注释。
- 只有导入、类型或状态声明且不含方法的脚本，不添加无意义的占位说明；模板表达式、样式和第三方自动生成文件不属于本次注释规则范围。

### 两行头部格式

方法或回调声明上方紧邻放置两行独立的 `//` 中文注释。计算属性、监听器和生命周期回调可将两行注释放在所属 `computed`、`watch` 或生命周期调用之前。

新增方法使用以下格式；示例日期与编号仅为格式示意，实际执行时替换为本次可核实的值：

```ts
// 创建时间：2026-10-22；调用记录：GPT-20261022-002
// 用途与逻辑：请求手动同步，拦截重复操作，记录开始时间并通知父组件刷新。
function requestRefresh() {
  // 同步尚未结束时不重复发送刷新事件，避免请求和反馈重叠。
  if (busy.value) return

  // 清理上一轮反馈计时，记录本轮开始时间，再进入加载状态。
  window.clearTimeout(feedbackTimer)
  startedAt = Date.now()
  feedback.value = 'loading'

  // 由父组件执行数据同步，本方法只协调交互状态与刷新通知。
  emit('refresh')
}
```

仅补充或修正文案说明、未改变方法行为时：

```ts
// 注释修改时间：2026-10-22；调用记录：GPT-20261022-002
// 用途与逻辑：关闭同步反馈，停止计时并回到空闲，视图更新后按需恢复按钮焦点。
```

修改已有方法行为、但无法核实原创建日期时：

```ts
// 修改时间：2026-10-22；调用记录：GPT-20261022-002
// 用途与逻辑：说明此次修改后的真实用途、主要步骤与必要的异常处理。
```

原注释中已经有可核实的创建时间时予以保留，可在第一行追加本次修改时间与调用编号，不扩展为第三行头部。任务历史保存在调用记录中，不在方法上堆叠历次日期或编号。

### 日期与维护要求

1. 日期使用 `Asia/Shanghai` 时区的实际操作日期，格式为 `YYYY-MM-DD`。跨日任务按实际修改日期标注，任务编号保留任务开始日。
2. 新建方法才能使用本次日期作为创建时间；现有方法历史日期无法核实时，不得使用当前日期冒充创建时间。
3. 第二行必须说明具体用途和实际实现，不使用“处理数据”“执行逻辑”等无法定位职责的空泛描述。
4. 修改校验、状态分支、缓存策略或异步顺序时，同步修正用途与步骤说明；移除方法时移除对应注释。
5. 已有两行头部直接维护，不重复追加头部；单纯读取方法不刷新日期。此前只有注释日期、尚无调用编号的方法，在下次涉及修改时再关联新编号，不批量补写历史编号。

### 关键步骤注释

说明应放在对应代码块或关键语句正上方，并与代码缩进对齐。优先解释“为什么需要这一步”及其输入输出或约束，重点覆盖：

- 前置条件、重复操作拦截、参数范围及缺失值处理。
- 数据筛选、身份匹配、格式转换与缓存回退，说明哪些值保持缺失。
- 请求发起、等待顺序、状态提交、定时器协调和异步结果失效处理。
- 存储写入、对话框操作、焦点恢复、事件注销和其他资源释放。

不为每条普通赋值机械加注释；一组共同完成同一职责的语句可使用一条步骤说明。不得借注释任务修改业务行为、模板、样式或无关文件。

## 调用留痕流程

### 开始任务

1. 阅读规则与当前调用记录，查看工作区已有改动，区分已有变更和本次工作。
2. 按 `GPT-YYYYMMDD-NNN` 分配编号，日期为任务开始时的上海日期，序号从 `001` 起递增。先查询编号是否存在；并行工作发现冲突时重新分配，子代理不得自行另建同一任务记录。
3. 在 `docs/gpt-call-log.md` 文件末尾追加“进行中”条目，记录开始时间、用户目标与预期范围。不要先将尚未执行的操作写成已完成。

### 执行任务

1. 仅在授权范围内修改；涉及 Vue 方法时维护两行头部和关键步骤说明，并在第一行关联当前任务编号。
2. 记录实际文件路径、重要方法、调整原因和行为影响；仅修改注释或文档时明确注明。
3. 留下重要工具动作、失败与处置摘要，不要求粘贴全部终端输出，不保存敏感信息。使用外部数据时说明来源类型和授权依据；网页抓取仍被禁止。
4. 验证从最小相关范围开始，记录实际命令、结果和未覆盖项；未执行、失败或依赖缺失不能写成“通过”。

### 结束任务

1. 将当前条目更新为“已完成”“部分完成”或“受阻”，填写结束时间；用户取消时如实标注“已取消”，不继续执行任务。
2. 写明验证结果、剩余问题和必要的下一步；只读分析写明“未修改业务文件”，不把追加记录误记成业务修改。
3. 核对实际差异与记录一致，保留本次任务开始前已存在的工作区修改。
4. 最终回复给出当前编号、记录路径和验证结论，便于从方法注释反查任务。

记录以追加新任务为原则。任务执行期间可以完善当前条目；后续需要纠正已结束记录时，追加带日期的更正说明，不悄悄覆盖原结论。若用户明确要求不写文件，只在回复中说明“未持久化记录”及原因，不绕过限制写入日志。

## 记录模板

以下占位内容必须替换为实际信息；不适用的字段写明原因，不编造会话 ID、模型名称、创建时间或检查结果。

```markdown
## GPT-YYYYMMDD-NNN · 任务标题

- 状态：进行中 / 已完成 / 部分完成 / 受阻 / 已取消
- 开始时间：YYYY-MM-DD HH:mm:ss +08:00
- 结束时间：实际时间；进行中时写“未结束”
- 用户目标：不包含敏感原文的任务摘要
- 实际范围：文件路径与相关方法；只读任务注明未修改业务文件
- 变更与原因：实际操作、行为影响，以及保留的已有改动
- 关键执行：重要工具动作；失败原因和处置（如有）
- 验证：实际命令及结果；未执行项和原因
- 剩余问题：未覆盖项、阻碍或后续建议；没有则注明无
```

## 自动化边界

当前采用项目指令、代码注释和本地 Markdown 任务记录实现协作留痕，依赖执行者按规范维护。没有新增自动审计服务、Git 钩子或运行时日志，也不能仅凭本文保证所有工具自动执行规则。

若未来接入 GPT API，应另行在服务端实现请求标识、时间、调用来源和结果状态等必要审计，并制定脱敏与保留期限；不得将密钥、Token、用户完整提示或模型原始响应直接写入日志。未实现前不得宣称具备运行时调用追踪。
